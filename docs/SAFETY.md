# 安全与信任边界 — 此刻有光

## 已落实（Milestone 1–2）

1. 用户可随时结束会话；结束会 abort 进行中的生成。
2. 真人接入需确认面板 + 双方确认状态（等待 → 申请 → 确认）。
3. 默认不公开完整 AI 对话历史；不将私聊默认同步到响应池。
4. 提供「举报」「阻止」入口（演示写入 FeedbackService）。
5. 公共请求不展示联系方式、精确位置或自由文本私密内容。
6. AI 消息强制标注「AI 陪伴」；演示回复标注「演示」；live 与 demo 分离。
7. 不虚构在线人数、匹配成功假象；演示操作有明确标注。
8. 文案声明：非专业心理咨询 / 非紧急援助。
9. 危机关键词触发服务端附加提示，要求审慎支持并鼓励现实求助；不把普通响应者当危机处置人员。
10. 未具备完整公网保障前，不向公众无限制开放陌生人聊天室；M3 为受控试点。
11. API Key 仅服务端环境变量；输入长度与调用频率有限制；上下文短窗口。
12. M3：访客身份由服务端签发；会话 ACL；原子匹配；举报/阻止落库；阻止后不可再匹配。
13. M4：真人消息拦截联系方式/链接外泄；危机内容附加系统求助引导（非危机干预）；公开请求主题标签过滤；开放/申请限流；管理者令牌可读取并复核举报（`MOL_COMPANION_ADMIN_TOKEN`）。
14. `publicOpen: false` 为显式产品闸门；未完成正式开放门槛前禁止无限制陌生人匹配。
15. M4.5：生产入口 `server/prodServer.ts`；可选 `MOL_COMPANION_INVITE_CODE` 服务端邀请码准入（不等于实名/年龄核验）；同源部署优先。

## 正式开放前必须具备

- 服务端授权与会话访问控制（受控试点已具备基础版）
- 限流与基本防滥用（基础版已具备；公网需更强边缘防护）
- 内容治理、举报阻止处置闭环（管理者复核 API 已具备；需人工值班流程）
- 可靠年龄策略（不能仅靠前端勾选冒充验证）— **当前仍为阻断项**
- 紧急求助引导的独立安全处理流程（关键词提示已具备；完整 SOP/热线对接仍为阻断项）
- 托管身份、HTTPS、数据库备份与审计日志 — **公网开放阻断项**
- 用户数据保留与删除/导出策略 — **公网开放阻断项**（试运行需书面告知保留期）

## 产品原则

- AI 永不假装真人
- 真人永不被未验证地标成「社区志愿者」
- 模拟模式不得包装成正式生产能力
